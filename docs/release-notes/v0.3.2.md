> **UGClient (UFClient) is a personal project in development. It is not an official UFACTORY product and is not affiliated with or endorsed by UFACTORY.**

UGClient (UI title **UFClient**) is a desktop client for kinematics, dynamics, 3D visualization, and optional physical arm control of UFACTORY robot arms, built on [`ufactory_genesis`](https://github.com/xArm-Developer/ufactory_genesis) (`v0.3.10`, `c167f1e`) and Pinocchio.

## UFClient branding & workbench refinements
- **UFClient identity:** Updated window/UI branding to **UFClient** with a custom geometric robot-arm vector logo (`AppLogo.vue`, `favicon.svg`).
- **Header & 3D stage cleanup:** Centered the real-robot status/connection trigger in `AppHeader.vue` (green indicator when connected cleanly, red when faulted, grey in simulation) and matched the 3D top-left indicator dot to green. Removed redundant `Stopped (4)` and engine status pills.
- **Smoother ergonomics:** Unified the `MotionPanel` collapse button across Cartesian and Joint tabs, reserved a stable right-sidebar scrollbar gutter (`scrollbar-gutter: stable`), switched default startup robot model from `uf850` to **xArm 6** (`xarm6_1305`), and enlarged default 3D robot framing by 50% (`VIEW_FIT` `1.35` -> `0.9`).

## Left navigation rail & Studio-aligned Settings
- **Navigation rail (`AppNavRail`):** Persistent left primary rail with **Live Control**, planned **Blockly / Python / GCode** placeholder entries, and bottom-left **Settings**, keeping the 3D WebGL viewport mounted across page switches.
- **Secondary Settings view (`SettingsView`):** Searchable 5-category settings workspace (**Motion**, **Externals**, **Safety**, **General**, **My Device**).
- **Unified Motion settings:** Separate **Joint Step**, **Position Step**, and **Attitude Step** click increments; **Collision Detection** sensitivity (`0–5`); per-model **Initial Position**; **TCP Payload & Offset** card with preset management; **Coordinates**; and **Mounting** presets (`Floor`, `Ceiling`, `WallUp`, `WallDown`, `Customized`).
- **Strict one-way read-only hardware sync (`real.read_settings`):** Reads `collision_sensitivity`, `world_offset`, `gravity_direction`, `mount_direction`, and `initial_point` from the physical controller into local state and never writes configuration parameters back to hardware (removed `real.set_tcp` and `real.set_payload`).

## 3D real-robot overlay & SDK fault recovery
- **Collapsible real-robot overlay (`StageRealInfo.vue`):** Top-left 3D card showing separated live controller State and Mode labels, normalized `vx.x.x` firmware version, collision sensitivity, **TCP Payload**, and **TCP Offset** alongside the model selector, with a read-only refresh button.
- **Redesigned controller fault card & Clear Error (`StageNotices.vue`, `MotionPanel.vue`, `realErrors.ts`):**
  - Replaced plain fault banners with a frosted-white floating error card showing the monospace controller fault code badge (`C1`–`C111`, e.g., `C19`), localized title and troubleshooting guidance from `xarm-python-sdk` (`End Effector Communication Error` / `末端工具通信失败`), optional warning code tag (`W*`), and persistent-fault feedback.
  - Added one-click **Clear error** actions on both the 3D fault card and `MotionPanel` guard banner following the `xarm-python-sdk` recovery sequence (`clean_warn` -> `clean_error` -> `get_err_warn_code` -> `motion_enable(True)` -> `set_mode(0)` -> `set_state(0)`). Faults are never cleared automatically, and motor re-enable is skipped if hardware faults remain latched (such as an active E-stop).

## End-effector controls & `ufactory_genesis` v0.3.10 (`c167f1e`)
- **Gripper controls (`RobotPanel.vue`, `lib/gripper.ts`):** Position slider/numeric input and Open/Close controls for **Robotiq 2F-85**, **Robotiq 2F-140**, **Gripper G2**, and **BIO Gripper G2**, with collapsible **Speed & Force** tuning and speed-estimated 3D finger animation in simulation plus `real.gripper_enable` / `real.gripper_move` RPCs on physical hardware.
- **State continuity:** Preserved compatible end effectors across `real.connect()` / reloads via per-model persistence (`endEffectorFor`), preserved the currently selected robot model on disconnect, and streamlined `RobotPanel` by removing redundant hint/mounting rows.
- **Upstream `ufactory_genesis` v0.3.10:** Added Robotiq 2F-85 (`173.253 mm` TCP) and 2F-140 (`245.466 mm` TCP) with the 11 mm flange adapter across UF850 and xArm 5/6/7, aligned Lite 6 meshes, `assembly.yaml` schema 5, semantic Draco attribute workaround (`draco.ts`) for swapped glTF Draco attribute IDs, and camera framing stability when swapping end effectors.

## Developer tooling
- Added `scripts/dev.py` to launch the Python JSON-RPC backend (`ugclient_core`) and Vite dev frontend together with automatic port/token handshake injection.

## Install / upgrade

### Linux (Ubuntu 22.04+, x86_64)
```bash
sha256sum -c SHA256SUMS.txt --ignore-missing
sudo apt install ./ugclient_0.3.2_amd64.deb
ugclient
```

### Windows 10+ (x86_64)
Download `ugclient_0.3.2_x64-setup.exe` and run the installer (English / Simplified Chinese). Verify the checksum against `SHA256SUMS.txt`. Because development builds are unsigned, Windows SmartScreen may show an "Unknown publisher" prompt on first launch.

## Supported models
UF850, xArm 5 / xArm 6 / xArm 7 (`_1305` revision only), Lite 6.

## Known issues
- Physical robot control has been hardware-verified on **xArm 6**; other supported models share the same adapter and are pending physical HIL verification.
- The **Externals** camera integration and **Blockly / Python / GCode** workspace pages remain placeholders planned for `0.3.3+`; joint torque table and target-pose IK UI are still API-only (`dyn.gravity`, `check.pose`, `kin.ik`).
- Installers are large (~100 MB) due to the bundled Pinocchio sidecar and are currently **unsigned**; macOS is not supported.
